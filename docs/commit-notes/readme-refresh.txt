docs(readme): turn the README into a project landing page

I rewrote the root README so a visitor can understand, run and evaluate the project in a few minutes. The old README read like a stage report: it listed every stage's test counts and setup caveats before it showed what the product does. I followed the structure common to well-known open-source READMEs: a one-line tagline, badges, a screenshot, the problem the project solves, features, an architecture diagram, a quick start, testing, the tech stack, the directory layout, a documentation index, a roadmap and contribution rules.

The features section is organized by role and by the AI safeguards: grounded citations, the read-only tool loop with per-call authorization, atomic human review, provider provenance, the optional LangGraph orchestration, the versioned knowledge base and the read-only MCP server. The quick start uses the existing compose.full.yaml and supportops.compose_demo commands; the manual setup moved into a collapsed section that links to the existing guides. The stage history is not lost: it remains in docs/progress.md and the dated evidence files, which the README links to.

I added three screenshots under docs/images/readme. I captured them from a disposable Compose project (supportops-readme, port 8091) with a throwaway env file outside the repository, so the existing local supportops-app stack and its volume were not touched. I activated the synthetic accounts, published and indexed the four bundled synthetic articles, created four synthetic tickets and ran one analysis with the default mock provider, which succeeded with one citation and two tool calls. Playwright captured the images at 1440x900, and I then removed the containers, volume and locally built images.

Validation: all 52 relative README links and image paths resolve, every in-page anchor matches a heading, the README renders through the GitHub Markdown API, the Mermaid diagram renders with Mermaid 11.4.1, and the repository language check passed. The test counts in the README come from the GitHub Actions run on main at cfd17d2: 421 backend tests, 53 frontend unit and component tests and 24 end-to-end tests passed.

Limitations: I did not repeat the quick start from a fresh clone on another machine or on macOS or Linux, and I did not re-run the manual setup commands. The screenshot's response draft is the mock provider's fixed text. The repository still has no license file; the README says so.
