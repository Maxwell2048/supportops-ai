feat(frontend): add ticket forms with conflict-safe drafts and write recovery

I connected the three roles to the existing ticket write API so requesters can submit and reply, staff can work through supported states, and managers can assign, prioritize, close, reopen and archive tickets. I kept server authorization and transactional rules authoritative and added only a manager-scoped active-agent read endpoint, with explicit identity-field projection.

Important changes and reasons:
- I added typed POST/PATCH/message contracts and safe error-code prompts without reflecting arbitrary API/proxy text. Resolving or waiting includes its public reply atomically; internal notes and public reopen reasons remain explicit.
- I retain draft text, assignment selections and the first edited version above query revalidation boundaries. A 409 reloads current data but requires explicit review and a separate submission rather than silently rebasing a stale draft.
- I bind UUID idempotency keys to the exact operation/payload. Unchanged retries reuse them; edits and reviewed versions replace them. For uncertain outcomes I lock editing and retry the original submitted body, even if current data changes, to recover a committed result safely.
- I prevent rapid duplicate sends with a synchronous guard and pending controls. Mutations do not automatically retry or queue offline. Successful writes invalidate current-session lists/details; authorization/conflict responses revalidate access/current state; mutation401 expires the session. Unmount aborts owned requests and suppresses late navigation.
- I added active-agent availability refresh and a retained unavailable selection that cannot be mistaken for unassigned. The server rechecks availability when saving.
- I extended the disposable loopback browser helper with delayed writes and one lost committed-response simulation. I added real PostgreSQL directory tests, write protocol/key tests and mutation-expiry coverage, and configured CI to run the write suite.
