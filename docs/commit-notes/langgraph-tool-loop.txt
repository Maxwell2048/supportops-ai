feat(analysis): add an optional LangGraph orchestration of the tool loop

I added an optional LangGraph StateGraph that runs the analysis tool loop as plan, execute and finish nodes with conditional edges, so the project shows the framework without giving it control. To keep one source of truth for enforcement, I first moved the body of the hand-written loop into a ToolLoop ledger in agent_tools.py. The ledger owns argument validation, the call budget, execution through run_call with its lease renewal and current role and object checks, the audit trace, the baseline title search and evidence ordering. The hand-written gather and the new graph only decide which ledger method runs next. Graph state holds the round counter and pending calls only, so no node update can reset the budget or insert evidence. Generation, citation validation and job completion still run once after either orchestration in execute_job.

I made the hand-written loop the default. ANALYSIS_LOOP=langgraph selects the graph through Settings, the worker passes the choice to execute_job, and an unknown value is rejected at startup rather than failing jobs. LangGraph is imported lazily, so the default path loads no LangGraph or LangChain module. The graph has no checkpointer, a recursion limit as a backstop to the round counter, and refuses to run, as does the worker at startup, when LangSmith or LangChain tracing variables are enabled, because the transitive langsmith package would otherwise export ticket text and passages. I pinned langgraph==1.2.24 with uv add, which updated uv.lock.

I verified with cd backend; uv run pytest: 110 passed and 264 skipped. All skips are PostgreSQL integration tests because TEST_DATABASE_URL was not set and no database was reachable in this session. The 25 new tests run both orchestrations against the same scripted planner and fake run_call and require identical traces, executed calls, planner inputs, evidence, context and errors across normal use, budget limits within and across rounds, the round limit, refused tools and arguments, rejection feedback, the evidence cap, a provider without a planner, stopped calls and planner failures. Removing the graph budget check, shifting its round limit or recording the wrong last round each made them fail. The existing loop unit tests pass unchanged. I parametrized the PostgreSQL tool-loop integration cases to run under both orchestrations, but they did not execute here. The repository language check passed.

Limitations: the integration cases, any real-model run on the graph path and remote CI are unverified. The graph adds a dependency tree for structure, not new capability, and deliberately does not use LangChain model wrappers, tool decorators or prebuilt agents.
