feat(analysis): let the model choose read-only tools under server control

I added a controlled tool step to analysis jobs. The model can now ask for knowledge search and ticket history before a draft is written, instead of the worker always running one fixed title search. The server offers only these two read-only tools, validates names and arguments with strict schemas, limits each job to three planning rounds and four budgeted calls, and runs every allowed call in its own short transaction that renews the job lease and re-checks the requesting staff member's current access, ticket version and archive state. Unknown tools, including write-like requests, are rejected and recorded. Ticket history is bound to the analyzed ticket and excludes internal notes because the draft becomes a public reply.

I kept the baseline authorized title search outside the budget and protected its passages from the evidence cap, so tool use can add evidence but never yields less than the earlier pipeline. Rejections return field locations and error types to the planner so it can correct itself, without echoing values. Migration 0010 stores the trace, the suggestion endpoint returns it as tool_calls, and the review workspace lists the calls as text. Providers without a planner keep the previous behavior. I documented the design in docs/agent-tools.md and ADR 0011.

I verified 339 backend tests with zero skips on local PostgreSQL, including new integration cases for per-call denial after reassignment, deactivation and ticket changes, lost leases, rejected tools and arguments, budget limits, internal-note exclusion and restricted knowledge. A clean frontend install, build, type check, 19 component tests, the API, query and write client tests, and 24 desktop and narrow browser cases with a separate mock worker also passed. Three local runs with the pinned 4B Ollama model produced validated citations on the final code.

Limitations: the local runs are a smoke check, not an evaluation. The model's own keyword queries found no passages and it repeated out-of-range limits; the baseline supplied the evidence. Model quality, adversarial tool use, latency and license provenance remain open. I did not migrate the development database or run remote CI in this stage.
